# Plan: Página de Venta — Editor interno + Landing pública configurada

## Resumen del análisis existente

### Estado actual relevante

1. **Tabla `organization_profile`**: Ya tiene `organization_id` como PK (1:1 con organizations), slug único, colores, horarios, descripción, privacidad, logo, etc. No tiene: hero_mode, hero_image_url, hero_title, hero_subtitle, galería, secondary_color, public_name, public_subtitle, public_zone, public_business_type, show_gallery, show_schedule, show_rating, rating_label, jobs_count_label, form_title, form_subtitle, is_published.

2. **Página pública `/solicitud/[empresa]`**: Server component que llama `solicitudesContactoService.getPublicRequestConfig(slug)`, que consulta `organization_profile` con admin client. Renderiza con colores configurados, logo, WhatsApp, formulario. CSS ya corregido (selector `*`).

3. **Página interna `/configuracion/empresa`**: Client component con `useOrganizationProfile()`, secciones para datos de empresa, marca, solicitud pública, notificaciones. Tiene preview, slug, copia de enlace, ver página pública.

4. **Navegación `app-shell.tsx`**: NAV_ITEMS con `/configuracion/empresa` como "Empresa" (LuSettings). Account menu tiene enlace a `/configuracion/empresa`.

5. **Storage**: Usa bucket `organization-assets` para logos. Se reutiliza para hero y gallery.

6. **RLS**: `organization_profile` usa subquery directa a `users`. `solicitudes_contacto` tiene policy `anon` INSERT. Lectura pública de org_profile usa admin client (server-only).

7. **Flujo formulario público**: `solicitud-empresa-form.tsx` POST a `/api/solicitud/[slug]`. No se toca.

---

## Decisiones de diseño

### 1. Extender `organization_profile` vs tabla nueva

**Decisión: Extender `organization_profile` con columnas nuevas.**

- Ya es 1:1 con organizations (PK = organization_id)
- Ya contiene slug, brand_color, horarios, descripción, privacidad
- Evita JOINs y sincronización
- Los campos nuevos son extensiones naturales de la landing

**Tabla nueva `public_landing_gallery`**: Sí, porque es 1:N (muchas fotos por organización).

### 2. Ruta interna

`/configuracion/pagina-venta` bajo `(pwa-app)`, agrupado con `/configuracion/empresa`. Se agrega a NAV_ITEMS.

### 3. Slug

Sigue en `organization_profile.solicitud_publica_slug`. No se mueve.

### 4. Página pública

Si `is_published = true`, usa campos de landing configurados. Si `is_published = false`, mantiene comportamiento actual (fallbacks a defaults). El formulario no cambia.

## Bug conocido: "Expected 'id' to be a string"

Este error aparece recurrentemente en consola y viene de `@supabase/gotrue-js`. Causas raíz identificadas:

1. **Sesión corrupta en localStorage** — El auth token almacenado tiene un `sub` (user id) que no es UUID válido. Solución: limpiar localStorage (keys `sb-*`) y reloguear.
2. **`getUserById` con bigint** — `web-push-notifications.service.ts:78` llama `supabase.auth.admin.getUserById(context.authUserId)`. Si `authUserId` se pasa como bigint de `public.users.id` en vez del UUID de `auth.users.id`, lanza este error.
3. **Versión de gotrue-js incompatible con token viejo** — Si se actualizó `@supabase/supabase-js`, el formato del token almacenado puede ser incompatible.

**Mitigación**: Durante QA de este plan, verificar que `authUserId` siempre sea el UUID de `auth.users`, no el bigint de `public.users`. Si el error persiste tras limpiar localStorage, auditar todos los callers de funciones auth que reciban un id.

## Riesgos y mitigaciones

| Riesgo | Mitigación |
|---|---|
| Romper formulario público | No tocar `SolicitudEmpresaForm`, solo pasar props adicionales |
| Romper flujo de solicitud | No cambiar lógica de `createPublicRequest` |
| Datos NULL en landing (org no configuró) | Fallbacks explícitos: publicName → empresaNombre, heroTitle → default |
| is_published = false muestra landing rota | Si false, renderizar exactamente como hoy |
| Bucket storage no existe | Reutilizar `organization-assets` que ya funciona |
| Slug duplicado | Ya hay unique index, se maneja igual que hoy |
| Overflow horizontal | max-width: 100% en imágenes nuevas |
