# Estándar de workflows Growth OS

Estado: vigente
Actualizado: 2026-08-14
Responsable: Growth OS

Todo workflow debe contener los bloques siguientes, en este orden:

1. **Objetivo**: movimiento concreto del embudo.
2. **Disparador**: cuándo se ejecuta.
3. **Entradas**: datos, lista, canal, usuario o evidencia requerida.
4. **Lectura obligatoria**: documentos y rutas que deben revisarse.
5. **Pasos**: acciones ejecutables, con responsable.
6. **Salida**: archivo, registro, mensaje, demo, prueba o decisión.
7. **KPI**: métrica primaria y unidad de medición.
8. **Siguiente acción**: responsable y fecha.
9. **Criterios de detención**: cuándo no continuar.
10. **Rutas afectadas**: solo si el workflow toca producto.
11. **QA**: validación manual y técnica requerida.

## Límites comunes

- Prospección manual y personalizada; cero spam.
- Un dolor, una demostración concreta y un CTA por pieza de contenido.
- Medir `mensajes -> demos -> pruebas -> primera cotización -> pagos`; no optimizar por vistas.
- No prometer más clientes, más ventas, cubicación universal, cortes exactos, nesting, CNC o producción automática.
- Si se toca código, leer `AGENTS.md`, `docs/agent-map/README.md`, ownership de ruta y QA antes de editar.
